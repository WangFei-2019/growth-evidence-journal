# 部署功能检查记录

检查日期：2026-10-14。目标为 GitHub Pages 独立静态版。

## 本轮确认并修复的问题

| 问题 | 修正后的行为 |
| --- | --- |
| 文件夹选择失败的说明显示在下面另一张卡片，容易被误认为没有反应 | 文件夹卡片独立显示进行中、成功、取消和错误状态 |
| 未区分浏览器缺少目录 API、HTTPS 或嵌入限制 | 根据实际能力显示文件夹授权或下载备份模式，并解释下一步 |
| 原生目录方法脱离 Window 接收者调用，授权前异步读取可能丢失用户手势 | 保留接收者，提前加载目录句柄，点击后直接申请权限 |
| 文件夹自动备份失败没有主动提示 | 显示中文错误说明，并对新的自动备份错误发出通知；工作档案仍独立保存在浏览器中 |
| 恢复入口拒绝超过 50 MB 的文件，可能无法恢复自己导出的合法附件备份 | 移除不对称的大小门槛，显示读取与解析进度，保留内容和附件校验 |
| 重选同一个备份文件不触发读取，旧的加密/普通预览可能混在一起 | 选择后重置文件输入框，读取新备份前清理旧预览，读取和解密期间防止重复操作 |
| 公开版仍写网页需要授权、API Key 切换后要重新填 | 帮助说明与公开访问及本机持久化行为保持一致 |

## 自动回归范围

使用 Node.js 24 执行 `npm test`，共 35 项检查：

- 文件夹选择的 Window 接收者、授权调用顺序、取消、拒绝、目录移动、用户隔离和断开。
- 一份实际 **53,128,741 字节（50.668 MiB）** 的虚构附件备份，完整通过读取、解码与档案验证。
- 加密备份实际加解密、错误口令、空文件、坏 JSON 与非法档案结构。
- 相同与相似记录提醒、批次重复、复核后编辑，以及既有记录排除自身。
- 引用原文的删除保护、附件恢复、旧证据恢复时保留新版本原文。
- 示例档案、跨日期工作归组、统一工作名称与标签、无效模型引用的待确认处理。
- 模型配置和密钥保存、清除密钥及本机用户隔离。
- 真实 React 服务端渲染检查：支持/不支持目录 API、HTTP、跨源嵌入和设置页组件接入。

GitHub Actions 同时执行回归测试、TypeScript 检查和带仓库子路径的生产构建。公开部署后另外检查首页及实际构建资源的 HTTP 访问。

## 尚不能作为已验证结论的部分

浏览器自动化连接在本轮持续超时，原生目录弹窗与实际磁盘授权使用模拟的浏览器接口验证，尚未完成桌面 Chrome/Edge 的实机点击回归。React 渲染测试不代替完整浏览器交互测试。

本轮没有读取使用者的浏览器档案或 API 密钥，没有调用真实模型。具体服务商的连通性、跨域策略和模型输出需在其实际 API 配置下测试。

## 静态版的能力边界

- 文件夹自动备份依赖浏览器授权，网页关闭后暂停。网页不能绕过系统或浏览器权限。
- 下载备份、记录与手动整理可独立使用；下载保存位置由浏览器决定。
- AI 整理直连使用者配置的 API，需要服务商支持浏览器跨域访问。
- 加密同步需要另行配置兼容服务；GitHub Pages 本身没有同步后端。
- 不同域名或浏览器的档案分别保存，需通过完整备份迁移。
